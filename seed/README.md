# seed/

Sample student roster for SonicAccess Phase 1.

## `students.json`

Generated by `npm run seed` (see `../scripts/README.md`). Shape:

```jsonc
{
  "$comment": "SAMPLE DATA — not for production.",
  "generatedAt": "<ISO timestamp>",
  "protocol": {
    "timeStepMs": 15000,          // rolling window
    "payloadBits": 44,
    "hotp": "HMAC-SHA1 / RFC 4226 dynamic truncation, key = secret as raw UTF-8"
  },
  "students": [
    {
      "studentId": 231800,        // 20-bit field, max 1_048_575
      "name": "Jumuad, Samantha Queen C.",
      "program": "BSIT",
      "section": "SBIT4K",
      "status": "active",
      "secret": "SZCGVTXAKJWPLFZ5WN6SEGG72R7O7OVQ",  // 160-bit, base32
      "deviceEnrolled": false
    }
  ]
}
```

## Who uses it

This is **not** bundled into the mobile app. Each phone stores only its own
`{ studentId, secret }` in the keychain (`src/services/authService.ts`).

`students.json` is the shared fixture for the other two sides of Phase 1:

- **Registrar / provisioning** — the source you hand a student their
  `studentId` + `secret` from (paste into the app's enrollment screen).
- **Gate node** — loads the same `studentId → secret` map so it can re-derive
  and check the rolling code it decodes from the chirp.

Both sides must use the identical `secret` string and the `protocol` values
above. See `../src/PROTOCOL.md` for the full contract.

## Regenerating

```bash
npm run seed -- --force
```

This rotates every secret. Any device already enrolled against the old file
stops verifying until re-enrolled, and the gate must reload the new file.

## Viewing the roster

```bash
npm run seed -- --show            # table of the current students
npm run seed -- --show --vectors  # + each student's live rolling code
cat seed/students.json            # raw file (secrets included)
```

`--show` never modifies the file. Plain `npm run seed` only creates it when
missing (it refuses to overwrite); use `--force` only to rotate all secrets.

## Manual QA with the app

1. `npm run seed -- --show --vectors` — note a student's `studentId`, `secret`,
   and current `rollingCode`.
2. In the app enrollment screen, enter that student's `studentId` and `secret`.
3. Tap **Emit gate pass**. The debug line's `code` should match the vector
   (within the same 15 s window).

## Security

Sample secrets are committed on purpose so the project runs out of the box.
A real deployment MUST generate fresh secrets, keep `students.json` out of
version control, and move the registrar/gate map to a secured store.
